# AI 正文审核规范 V1.0

## 1. 审核目标

审核不是“夸写得好不好”，而是主动找会损害商业阅读体验的问题。

最高目标：

> 好看、不断章、像人写、职业逻辑不胡扯。

以下任一重大问题出现，必须退回：违反 Canon、专业事实明显错误、剧情没有有效推进、金手指越界、和前文产生重大矛盾。

## 2. 审核输入包

每次审核至少提供：

- 《产品说明书》
- 《金手指规则》
- 《主角与世界设定》
- 当前阶段目标
- 当前章节卡
- 当前状态表
- 最近 5—10 章摘要
- 本章正文
- 必要的职业资料库条目

长篇不必塞全部历史正文。

## 3. 错误等级

- **P0 致命**：违反核心产品/世界/金手指规则，整章不得发布。
- **P1 严重**：专业错误、人物崩、核心逻辑失败、严重重复，修改后复审。
- **P2 一般**：节奏、措辞、轻微逻辑、少量 AI 味，局部修订。
- **P3 优化**：可改可不改，不影响阅读，不必为了挑刺而改。

## 4. Canon 硬规则审核

以下情况直接 P0：

- 系统直接告诉准确故障和维修步骤；
- 系统直接送钱、房、车、物品；
- 系统扫描人物属性、好感度、财富、疾病；
- 系统预测未来、投资走势；
- 系统新增商城、抽奖、签到、任务积分；
- 主角突然获得医术、黑客、格斗等无关技能；
- 世界新增第二种超自然体系；
- 主角突然变隐藏天才/权贵后代；
- 前期直接修飞机、军工、精密机床等；
- 维修升级成“万物皆可修”。

如剧情确实需要突破，只能输出 `【Canon变更申请】`，不得擅自改规则。

## 5. 主角主动性审核

每章必须问：结果是主角挣来的，还是系统替他完成的？

合格：状态提示 → 主角观察 → 判断 → 选择 → 行动 → 承担结果。

如果系统提示几乎等于答案，主角只按说明操作，判 P1。

## 6. 职业真实性审核

重点检查：

- 设备基本原理；
- 故障与症状是否大体匹配；
- 正常维修人员是否会这样处理；
- 电气、制冷、机械等安全边界；
- 主角是否越过职业资格与能力范围。

尤其防止：

- 把所有“不制冷”都写成缺冷媒；
- 把所有结冰都写成除霜器坏；
- 混淆压缩机、冷凝器、蒸发器作用；
- 胡编冷媒、压力、温度关系；
- 乱写 PLC 参数、型号、国家标准。

无法确认时输出 `【待事实核验】`，禁止继续编一个“正确答案”。

## 7. 专业描写审核

原则：**有专业感，不写教材。**

- 单章原则上最多引入 1—2 个新的专业概念。
- 禁止大段参数、零件型号堆砌、危险操作、虚构国标、几十行 PLC 代码、精确冷媒操作教程。
- 读者只需要知道“它是干什么的”和“为什么与当前现象有关”。

## 8. 经济逻辑审核

每次涉及钱，检查：

- 金额；
- 成本；
- 利润；
- 付款逻辑。

禁止：

- 普通小维修突然收数万元/数十万元；
- 后期仍靠低价小单维持财富增长；
- 同一种维修随着剧情推进价格凭空翻几十倍。

正确升级应来自：小单 → 商业急修 → 高价值设备 → 稳定客户 → 维保合同 → 翻新资产 → 团队业务。

## 9. 剧情推进审核

核心问题：

> 删掉这一章，故事会不会几乎没变化？

如果删除后对技能、钱、客户、资产、身份、关系、信息、风险、决策结果都无影响，则判 P1“空转章节”。

一章不要求大升级，但至少要改变一个状态。

## 10. 爽点审核

核心爽点顺序：

> 专业爽 > 时间压力爽 > 财富/价值爽 > 身份升级爽 > 事业爽。

每个小单元结束，原则上至少兑现两项，例如：

- 问题解决 + 收钱；
- 技术证明 + 客户升级；
- 资产判断 + 财富收益；
- 风险解除 + 长期合作。

## 11. 降智打脸审核

如果连续单元都采用：

> 同行/老板嘲笑 → 主角出手 → 众人震惊

则判重复风险。

优先冲突来源：

- 时间；
- 损失；
- 成本；
- 责任；
- 风险；
- 信息差；
- 不同方案；
- 资源不足；
- 多订单冲突。

大多数高潮即使删掉“反派羞辱”也应成立。

## 12. 重复度审核

不能只比较设备名称。

必须比较六个维度：

> 故障性质 × 利益相关者 × 时间压力 × 主角选择 × 收益类型 × 客户关系。

最近 3 个单元中，如果“核心冲突 + 主角解决方式 + 收益方式”有两项以上高度相同，标记 `【重复风险：高】`。

修复方式应换冲突机制，而不是只换机器。

## 13. AI 味专项审核

重点抓：

- 同义重复；
- 机械排比；
- 每章结尾强行升华；
- 角色说话同声；
- 震惊/倒吸凉气/瞪眼模板反应；
- 过度心理解释；
- 无效环境描写；
- 不必要的精确数字；
- 段落结构过分工整；
- 大量“不是……而是……”等固定模型句式。

目标：删掉模型为了显得完整而制造的废话。

## 14. 章尾审核

不要求每章都硬悬念。

优先使用真实剧情动力：

- 新订单；
- 未解决异常；
- 客户来电；
- 结果反转；
- 利益选择；
- 下一步行动。

避免每章都以“他知道，这只是开始”式总结收尾。

## 15. 人物连续性审核

重点检查：

- 姓名、年龄、职位；
- 人物关系；
- 已知信息；
- 说话方式；
- 技能边界；
- 前后态度变化是否有原因。

长期状态改变必须写入状态表。

## 16. 金手指连续性审核

每次面板出现都对照：

- 当前职业熟练度；
- 已解锁设备类别；
- 当前面板精度；
- 价值识别是否已开启。

如无升级却突然从“制冷循环”精确到具体坏件，直接 P0。

## 17. 节奏审核

以 5—10 章单元观察，不机械要求每章都爽。

正常单元应有：

> 问题建立 → 信息不足 → 判断/选择 → 阻碍或变化 → 解决 → 收益/状态变化。

避免：

- 前几章一直聊天不进入事件；
- 第一页就系统给答案，后面纯灌水。

## 18. 长期阶段审核

主角角色应逐步变化：

维修执行者 → 诊断者/独立服务者 → 客户与资产经营者 → 团队负责人/服务商。

若 50 万字以后仍天天亲自处理低价小单，属于产品结构失败。

## 19. 发布闸门

最终只允许三种结论：

- **PASS**：无 P0/P1，可发布。
- **REVISE**：有 P1，修改后复审。
- **REWRITE**：有 P0 或本章核心结构失败，整章重写。

禁止输出“总体不错，稍作润色”这类无决策价值结论。

## 20. 固定审核输出格式

```text
【最终判定】
PASS / REVISE / REWRITE

【P0 致命问题】
无 / 具体问题

【P1 严重问题】
无 / 具体问题

【P2 一般问题】
只列真正影响阅读的问题

【专业真实性】
具体风险；不确定项标记【待事实核验】

【Canon检查】
金手指、主角、世界、设备类别、熟练度、资产、人物状态

【重复度检查】
与最近剧情比较六个维度

【AI味检查】
列出具体机械化表达

【本章有效状态变化】
一句话说明本章实际改变了什么

【最小修改方案】
优先保留原文，只修真正的问题

【发布结论】
可以发布 / 修改后复审 / 整章重写
```

## 21. 实际生产流程

普通章节：

> 正文模型生成 → 审核模型质检 → 正文模型修订 → 最终审核 → 发布。

涉及真实制冷、电气、报价、设备原理的重专业章节，再额外增加一次职业真实性专项审核。
